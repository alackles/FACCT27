| 2026-10-21 | Hub identification uses Kirkley 2024 (MDL hub classification, *PRE* 109, 034310) on contexts-weighted in-degree, i.e. per node the sum over repliers of the number of threads in which they replied to it, with the multigraph encodings (Eqs. 8–9). | 2026-10-21 | Kirkley hub sets reported under the CM encoding for every window (primary and secondary runs). | 2026-10-21 | Kirkley implementation conventions: N = all nodes in the window graph, including in-degree-0 nodes (repliers who received no replies); nodes of equal degree are added to the hub set as one block (Kirkley's tie option), so results are deterministic; the scan covers every *h* from 0 to N and takes the global minimum of description length rather than stopping at the first increase; description lengths in bits, log-binomials via `scipy.special.gammaln`. | 2026-10-21 | **Correction** to the 2026-10-21 CM-primary row: its rationale that CM is "the more conservative encoding" is wrong for this network. | 2026-10-21 | Both encodings are reported as distinct measures, superseding "CM primary". **ER** hubs are nodes of comparable, extreme degree that stand apart from everyone else; the ER encoding treats hubs as one interchangeable block, so *h*\* = 1 means a single outlier with no group of similar size. **CM** hubs are the nodes outside the homogeneous bulk; CM describes each hub's degree individually and the remainder as uniform, so in a heavy-tailed network its hubs are the tail. CM is the more compressive description where `er_wins` is false; the flag is kept. Divergence after the first real run. | Acacia | The two answer different questions about the same data, and the difference is informative (e.g. one outlier plus a heavy tail). Reporting only the encoding that tells the cleaner story would be selection after seeing results. |
