| 2026-10-08 | Self-deleted content (`_meta.removal_type == "deleted"`) kept in raw, excluded from analysis; in the processed layer it becomes a tombstone (ids, parent, timestamp kept; text and author nulled). Count reported in the paper. | Acacia | Respects authors' retraction while keeping reply-tree structure intact; reversible. Limitation: Arctic Shift only detects deletions within ~36 h of posting, so later deletions are invisible to us. |
| 2026-10-08 | Moderator-removed content (`_meta.removal_type == "moderator"`) kept and analyzed, flagged. | Acacia | Removal is the community's boundary-keepers acting, not the author retracting; what moderators remove is data about community norms. |
| 2026-10-08 | Pagination: per calendar month, `sort=asc`, next page `after = last created_utc - 1`, dedupe by id. Comments from `/api/comments/search` by subreddit, not per-post trees. | Claude | Verified 2026-10-08 that `after`/`before` are exclusive, so `after = last` would silently drop same-second ties at page boundaries. Month windows avoid API timeouts and give a resume unit. `parent_id`/`link_id` suffice to rebuild trees in ~10x fewer requests. |
| 2026-10-08 | Text only: images, galleries, and linked media are not collected. | Claude | Scope limit for v1; stated as a limitation. |
| 2026-10-08 | Stored text is the version first fetched (~25 s after posting); later edits are not captured, only flagged (`_meta.is_edited`). | (observed) | Inferred: edited items carry `edited=False` and Arctic Shift's second fetch updates scores/flags, not text. Limitation: in-place edits ("EDIT: patched") are invisible. |
| 2026-10-08 | Pseudonyms (C1, C2, …) assigned in seeded random order, keyed on author string; map and seed stored in `data/private/`. `u/handle` mentions in text replaced by the pseudonym, or `u/[user]` if not in corpus. | Claude (de-identification: authors to confirm) | Activity-ranked numbering would make C1 the most active user, likely identifying the ENI creator. Random order carries no information. |
| 2026-10-08 | Admin-removed content (`_meta.removal_type == "reddit"`) kept in raw and processed, flagged `needs_review`; disposition decided item by item by the authors. | Acacia | Reddit admin/spam-filter removals may include content Reddit judged too harmful to host, so a human decides each case rather than a blanket rule. |
| 2026-10-08 | One pseudonym map shared by all snapshots (`data/private/pseudonyms.json`, `seed.txt`): existing assignments never change; authors new to a snapshot are shuffled and appended. | Acacia | A pseudonym quoted in the submitted paper must still refer to the same person if data are re-collected for revision. |
| 2026-10-08 | Reddit system accounts (AutoModerator) keep their name rather than a pseudonym. | Acacia | Infrastructure, not a person. Whether it becomes a graph node is a stage-2 edge-definition call (it replies to most posts and would look like a pole). |
| 2026-10-19 | Comments with `_meta.removal_type == "removed"` kept and analyzed, flagged, as for `moderator`. 791 in the 2026-10-08 snapshot, all with text captured before removal. | Acacia | Most likely moderator or AutoModerator removals, which Reddit doesn't distinguish on comments (inferred; Arctic Shift doesn't document the value), so the moderator rationale carries over. Too many for item-by-item review. |
| 2026-10-19 | `_meta.removal_type` values `content_takedown` (10 posts) and `removed by reddit` (2 comments) handled as `reddit`: kept, flagged `needs_review`. | Acacia | Both appear to be Reddit-side, not moderator, removals (inferred; values undocumented by Arctic Shift), so the `reddit` rationale applies; 12 items is cheap to review by hand. |
| 2026-10-19 | Items whose text was already `[removed]`/`[deleted]` at first fetch (`excluded_reason == "text_unavailable_at_collection"`; 384 posts, 851 comments) stay in the processed layer and are excluded at graph build. Whether ones with replies in the corpus are kept as text-less edges is still open. | Acacia | Removed within ~25 s, so most were likely never seen and aren't interactions. Keeping the processed layer a faithful de-identified mirror puts analytic exclusions in the graph build, where they're visible parameters. |
| 2026-10-19 | Edge = reply: a comment's author → the author of its parent comment, or of the post for top-level comments. `u/C…` mentions form a separate layer, analyzed separately. Co-thread edges not used. | Acacia | Reply is directly observed and was seen by the community, the closest analogue to Zachary's interaction. Mentions catch a pole talked *about* more than *to*. Co-thread measures shared attention, and large threads swamp it. |
| 2026-10-19 | Edges stored directed; symmetrized for min-cut and path-based centrality. In-strength and reciprocity use direction. | Acacia | Zachary's flow model is undirected; direction distinguishes broadcasting poles from conversing ones. |
| 2026-10-19 | Edge weight = number of distinct threads in which the pair interacted (either direction, union); raw reply count kept for sensitivity runs. | Acacia | Zachary weighted by number of contexts of interaction. Check (Claude, `networkx` karate graph): weighted min-cut misplaces only individual 9, as Zachary reports; unweighted misplaces two. |
| 2026-10-19 | Whole period (2025-02 to 2026-09) is the primary graph; `--start`/`--end` allow time slices. | Acacia | Volume halved after mid-2026; slices test whether the poles persist across that change. |
| 2026-10-19 | Pole candidates identified from the data: top-k by centrality, pairwise min-cut between them, graph visualized before any pole is chosen. Degenerate cuts (no better than isolating the weaker pole) are reported, not filtered. | Acacia | Look at the structure as it is before committing to which figures are poles. |
| 2026-10-19 | AutoModerator excluded from the graph. Human moderators included, with node attribute `mod` (= posted any moderator-distinguished item in the window); `--exclude-mod-actions` drops distinguished items for sensitivity. | Acacia | AutoModerator would be a false hub. Moderators are participants and plausible poles. |
| 2026-10-19 | Items without an author (tombstones, deleted accounts) are not nodes; replies to them are dropped and counted. | Acacia | One node per item floods the graph; one merged node is a false hub; re-attaching replies invents interactions. Also respects retraction. |
| 2026-10-19 | Instant removals (`text_unavailable_at_collection`) kept as edges when replied to in the corpus, otherwise dropped. `needs_review` items included, flagged per edge; `--exclude-needs-review` drops them. | Acacia | A reply proves the item was seen. In this snapshot, instant-removed comments have no author, so in practice the rule only affects posts. |
| 2026-10-19 | Graph conventions: nodes = authors with ≥1 kept edge (authors without edges counted); self-loops and replies to missing parents dropped and counted; no degree/k-core pruning; path-based measures use distance = 1/weight; defaults top-k = 5 per measure over strength, in-strength, betweenness, closeness (Freeman's three plus in-strength). | Claude (defaults: authors to confirm) | Every exclusion is counted so the paper can report it. Pruning changes min-cut results, so it stays off unless chosen. |
| 2026-10-19 | Exploratory network view (`facct27.viz`): clusters are Louvain communities (`networkx`, resolution 1.0, seed 0) on the undirected contexts-weighted graph; the three largest are colored, the rest grey. The HTML file embeds pseudonyms and counts and stays local. | Claude (exploratory; authors to confirm before any cluster is reported) | Louvain is the standard modularity method and needs no cluster count. Seeded because it's stochastic. Three colors because node-link plots compare every color pair, and only three palette slots stay distinguishable under that test. |
